# 三阶段主线与最终原作复现：模型编程工具库及其效果

2026-11-06。按用户最新要求重整研究优先级。本文是后续工作的主路线，优先于旧记录中将HotpotQA或FinQA作为主应用的选择。用户已重新激活并更新目标；早期仅完成设计；2026-11-07首个实验性工具库现已开源，专业OfficeBench执行移植已接通并开始4B个案运行，完整协作与参数编程收益尚未建立。最终增加独立复现MIT实验并比较编辑方向，见[专门协议](mit-wsp-reproduction.md)。

## 1. 通用工具与研究分工

WSP-toolkit 提供独立的观测、解释、干预、编辑和评测能力。模型适配器声明站点与权限，任务配置声明数据和指标。法律、财会、办公和通用任务共用接口。原作复现沿用持久 Python、直接权重读写和预算内前向的权限配置。

现有实现、待封装接口和新方法按同一个工具 ID 记录。建设顺序为通用接口与已有实现归并、基础可解释性方法、特征与计算路径插件。已实现的激活替换、TIES、Wanda 与 SparseGPT 均在各自原实现上接入。 [工具设计与合并路线](wsp-toolkit-tool-design.md#9-已有实现与合并路线) · [工具目录](toolkit-design-catalog.json)

## 2. 第一阶段：可独立使用的开源工具库

1. 公开 MCP 模型调用接口和可直接使用的 Python 接口，共用工具定义与执行代码。先验证模型能力查询、激活采集和产物切片，再扩展公开工具。提供支持矩阵、安装说明、方法依据和第三方许可。 [接口设计](wsp-toolkit-tool-design.md#mcp-与-python-接口)
2. 提供只读解释与权重编辑两条教程。只读教程覆盖快照、热力图、概念或层级分析和临时干预。编辑教程覆盖已有权重编辑或压缩算法、候选版本和配对评测。
3. 用 Qwen3 与 Llama 的真实检查点验证相同接口，用 Qwen3.5 核对混合架构站点能力。另以真实分类编码器验证观测接口的适用范围。
4. 导出可重放的运行记录、模型版本和证据文件，供后续 0.6B 和 4B 实验复用。 [公开发布记录](open-source-release.md) · [工具设计](wsp-toolkit-tool-design.md#8-三阶段的交付与实验)

## 3. 第二阶段：0.6B模型上的可解释性能提升

主目标是检验工具库能否产生可重复的能力收益；领域保真压缩是另一个目标，分别报告。

以Qwen3-0.6B为主验证模型，保留同系列1.7B和另一系列模型用于趋势对照。正式结果使用完整公开分区与独立种子。已有统一协议下485→532→590/1319的原模型／标准LoRA／固定缩放结果是起点，不等于LLM程序设计者优于普通方法。

建议分开三个实验问题：

| 实验 | 固定什么 | 比较什么 |
|---|---|---|
| 工具作用 | 数据、基础模型、方向来源与预算 | 原模型、标准LoRA、单工具、工具组合 |
| 观测价值 | 可选操作、查询／训练预算 | 无内部观测、统计观测、因果干预观测 |
| 程序设计者价值 | 相同工具、数据、权限、总成本 | 固定配方、随机／BO、LLM选择 |

GSM8K用于可复核的推理效果，ARC-C／HellaSwag用于跨任务损伤；可增加专业子能力，但不能把专业选择题高分称作工作流胜任。报告准确率、逐题改善／退化、输出接口、实际训练／搜索成本；压缩另报告质量—存储—延迟前沿。

明确区分无梯度更新、梯度观测、允许训练的实验。使用已训练方向也要计入该方向的训练来源与成本；“搜索无训练”不等于完整路线无训练。

阶段产出：可复现实验程序、真实效果／失败案例、单工具与组合消融、跨规模／系列差异分析，以及可下载的适配器／selector与完整程序记录。

## 4. 第三阶段：4B模型在专业多Agent工作流中的参数编程

本阶段被修改的目标模型是4B。程序设计者`M_programmer`与目标`M_target=4B`分开记录；不再默认4B仅作为教师，最终效果来自更小学生。程序设计者可以更强，但必须单独计入它的构造成本。

先比较同一4B的强单Agent、多步修订／独立采样与多Agent工作流；建立协作收益后，固定拓扑、工具权限、文件表示和预算。然后修改各角色4B的参数，以同基座＋角色delta表达，测单角色和联合替换。角色专用化是本阶段的优化方式，不应替代对整个4B工作流的验证。

必须比较：未编辑4B工作流、普通角色LoRA、统一多任务adapter、非LLM同工具搜索和LLM参数程序。教师轨迹、额外训练数据、prompt变化、工具后端变化要分别控制。若把RAG或文件解析做得更好，应记录为环境／输入改善，不能计为参数编程收益。

### 4.1 专业工作流候选及选择

| 数据集 | 能评什么 | 与本项目的关系 | 接入时必须解决的事项 |
|---|---|---|---|
| [Finch／FinWorkBench](https://arxiv.org/abs/2512.13168) | 172个财会组合流程、384个任务，跨表格和文件的专业工作 | **专业复杂度主候选**；适合数据整理、财务分析、成果复核角色 | [官方管线](https://github.com/FinWorkBench/Finch)含文件预处理与judge；Excel／多模态处理、评价依赖和人类评分对齐需核实 |
| [OfficeBench](https://github.com/zlwang-cs/OfficeBench) | 300项跨应用办公任务，匹配及执行类评价 | **首个接入与方法开发桥梁**；便于测计划、执行、跨应用协作 | 固定应用状态与动作接口，保留官方评分；工具输出不能暗中由更强模型代做 |
| [LegalAgentBench](https://github.com/CSHaitao/LegalAgentBench) | 中文法律的300项任务，17类语料、37个外部知识工具，含过程指标 | **中文法律迁移主候选**；研究检索、证据串联、写作角色 | 逐项核实语料和工具服务能否本地复现，以及评分所需的中间监督 |
| [Harvey LAB](https://github.com/harveyai/harvey-labs) | 围绕案件材料产出法律工作成果，含任务与执行／评分框架 | **高难法律成果扩展**；比法律知识问答更符合专业工作目标 | 固定release。当前[官方评分](https://github.com/harveyai/harvey-labs/blob/main/docs/eval-strategies.md)以rubric及LLM判断为核心，需专家抽查与裁判一致性分析 |
| [TheAgentCompany](https://github.com/TheAgentCompany/TheAgentCompany) | 模拟公司的175个任务镜像，覆盖办公和职场协作 | 用于跨角色／状态交互扩展 | 环境容器、同事模拟与环境LLM成本较重；不能把环境模型当免费的辅助能力 |
| [GDPval](https://openai.com/index/gdpval/) | 公开gold集220项，覆盖44职业的专业成果 | 外部成果质量检验 | 首版是one-shot交付评价，不是原生交互工作流；若构造多Agent，标为本项目系统设计 |
| [APEX-Agents](https://www.mercor.com/blog/introducing-apex-agents/) | 投行、咨询、公司法的长程专业任务和工作空间 | 高难综合迁移候选 | 先核对任务、环境与rubric的固定版本和可重复部署条件，再决定投入 |

推荐采用“OfficeBench打通执行与归因→Finch做财会主实验→LegalAgentBench或Harvey做法律迁移”的顺序，不要求同时跑七套完整系统。这里的顺序是基于任务形式与当前实现的研究判断，不是这些任务已适合4B或多Agent的实测结论。

HotpotQA退居通用机制对照；FinQA保留为财务推理及既有失败分析。它们不能替代上述专业工作成果实验。

### 4.2 专业评价的几个必要区别

工作流数据集不自动证明多Agent更好。工具执行失败、专业推理错误、格式问题、成果缺失和裁判分歧应分开统计。完成率、关键约束通过率、事实／数字／引用正确性及实际耗时均需保留；rubric平均分与整任务all-pass分别报告。

4B文本模型处理表格、PDF或图像，需要固定且公开的解析／执行工具。如果使用视觉模型辅助，须明确其角色、成本和全部条件是否相同。若只能支持部分任务，按输入能力预先声明任务范围，报告覆盖率；不能评测后剔除失败任务或将子集分数称为完整benchmark。

公开任务没有训练分区时，优先另建独立开发／训练任务，再将公开集保留作确认。若必须自行划分，按工作空间、源文件谱系、案件／公司分组，并明确命名为derived split；不能把同一工作流下相依任务分别放进训练和测试，也不能让期望成果文件进入performer输入。

复杂流程上若所有4B条件都接近零，先判别环境和输出接口是否可用，以及任务容量瓶颈；保留失败结果，不靠隐藏简化或额外强模型代做制造提升。

## 5. 工具选择的解释标准

一个候选工具进入核心库，应能形成完整链条：

> 工作中可观测的失败／资源问题 → 文献中的对应假设 → 本模型上可取得的统计／监督 → 合法更新 → 可证伪的效果指标。

例如：角色输出协议不稳定，先看角色监督和适配；组合更新互相抵消，研究更新算术及合并干扰；显存／延迟过高，研究秩和结构压缩；删后能力下降，研究补偿与恢复；某行为归因不清，先做干预诊断。它们各有用途，不能以“工具多”代替方法上的互补性。

第一阶段证明工具库有理有据且可用；第二阶段证明其在小模型上产生可解释的真实效应；第三阶段证明这些操作能改善4B专业工作流。三个阶段分别有可交付结果，最终连成同一研究主线。

## 6. 最终阶段：原作效果复现与方向对照

目标模型单独固定为原作Qwen3.5-0.8B，不能用第二阶段的Qwen3-0.6B替代。先以作者差分校准参考重放，再让新的隔离程序设计者仅从原模型、练习数据与通用工具独立分析。当前会话已经读过参考解，不能把其后续编辑算作盲发现。

无训练主轨道冻结模板、采样、预算和评分；最终编辑冻结后才测完整数学任务。效果达到预先定义的标准后，再比较两者的层／列支持、参数方向、子空间、共同输入上的功能变化及因果干预。原作重放、独立发现与方向比较分别交付，不能只完成其中较易的一项便称复现成功。具体原始来源、已补原语及缺口见[mit-wsp-reproduction.md](mit-wsp-reproduction.md)。
